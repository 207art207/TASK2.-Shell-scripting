# TASK2.-Shell-scripting

Репозиторій містить результати двох завдань:

1. Створення локального й віддаленого Git-репозиторіїв та їх merge.
2. Bash-скрипт базової ініціалізації репозиторіїв.

## 1. Завдання з Git: базовий рівень

### 1.1. Створення локального репозиторію

Для проєкту використано директорію `~/Projects/TASK2.-Shell-scripting`.

```bash
mkdir -p ~/Projects/TASK2.-Shell-scripting
cd ~/Projects/TASK2.-Shell-scripting

git init -b main
```

Команда `git init` створює локальний репозиторій і службову директорію `.git`. Параметр `-b main` задає назву початкової гілки.

### 1.2. Створення віддаленого репозиторію

На GitHub окремо створено репозиторій `TASK2.-Shell-scripting`.

За умовою завдання репозиторій повинен мати видимість **Public**.

Початковий віддалений коміт `a61530a` містив файл `README.md` із назвою проєкту.

### 1.3. Додавання файлів локально

У локальному репозиторії підготовлено порожні файли скрипту та конфігурації:

```bash
mkdir -p utils/.configs

touch utils/git-init.sh
touch utils/.configs/git-myconfig

git add utils/git-init.sh utils/.configs/

git commit -m "Add: utils/git-init.sh script and hidden config directory ./configs"
```

- `mkdir -p` створює директорії.
- `touch` створює порожні файли.
- `git add` індексує зміни.
- `git commit` зберігає цей вміст в історії репозиторію.

Початковий локальний коміт: `e5dbeff`.

### 1.4. Додавання файлу через браузер

До віддаленого репозиторію через інтерфейс GitHub завантажено зображення `git-browser-file-upload.png`.

Цю дію відображає коміт `90a44a7`:

```text
Add: file from browser in repository
```

Таким чином, перед об’єднанням локальний репозиторій містив файли в `utils`, а віддалений — `README.md` та зображення.

### 1.5. Зв’язування репозиторіїв та узгодження їхнього вмісту

Після створення комітів з обох боків до локального репозиторію додано адресу віддаленого:

```bash
git remote add origin git@github.com:207art207/TASK2.-Shell-scripting.git
```

`origin` — умовна назва віддаленого репозиторію.

Для отримання віддаленої історії використовується:

```bash
git fetch origin
```

`git fetch` завантажує об’єкти й оновлює посилання на віддалені гілки.

Для об’єднання історій:

```bash
git merge origin/main --allow-unrelated-histories
```

Локальний і віддалений репозиторії створювалися незалежно, тому їхні початкові коміти не мали спільного предка. Параметр `--allow-unrelated-histories` дозволяє таке об’єднання.

У результаті створено коміт злиття `f2a139c`:

```text
Merge remote-tracking branch 'origin/main'
```

До локального робочого дерева додалися `README.md` і `git-browser-file-upload.png`, а локальні файли в `utils` збереглися.

Після цього об’єднану історію передано на GitHub:

```bash
git push -u origin main
```

`git push` передає локальні коміти у віддалений репозиторій. Параметр `-u` налаштовує зв’язок локальної гілки `main` із `origin/main`.

Для перевірки стану та історії використовуються:

```bash
git status
git log --graph --oneline --decorate --all
```

### 1.8. Додавання .gitignore

У `.gitignore` додано шлях до локальної конфігурації:

```gitignore
utils/.configs/git-myconfig
```

Оскільки порожній конфігураційний файл уже потрапив до першого локального коміту, одного правила ігнорування було недостатньо. Для припинення його відстеження використовується:

```bash
git rm --cached utils/.configs/git-myconfig
git add .gitignore

git commit -m "Add: .gitignore file and remove tracking utils/.configs/git-myconfig"
git push
```

Параметр `--cached` прибирає файл з індексу, залишаючи його на диску.

Цей етап зафіксовано комітом `2c06f2f`. У попередній версії конфігураційний файл був порожнім.

## 2. Скрипт базової ініціалізації Git-репозиторію

### 2.1. Призначення

Скрипт `utils/git-init.sh` автоматизує:

- створення директорії проєкту;
- ініціалізацію локального Git-репозиторію;
- установлення локальних `user.name`, `user.email` та `init.defaultBranch`;
- створення `README.md` із назвою проєкту;
- додавання віддаленого репозиторію під назвою `origin`.

Для роботи потрібні Bash і Git.

### 2.2. Структура проєкту

```text
TASK2.-Shell-scripting/
├── .gitignore
├── README.md
├── git-browser-file-upload.png
└── utils/
    ├── git-init.sh
    └── .configs/
        └── git-myconfig
```

Файл `utils/.configs/git-myconfig` існує локально та не відстежується Git.

Шлях до конфігурації визначається відносно розташування скрипту:

```bash
SCRIPT_DIR=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd) || exit 1
CONFIG_FILE="$SCRIPT_DIR/.configs/git-myconfig"
```

### 2.3. Конфігурація

Приклад із демонстраційними значеннями:

```bash
USER_NAME="my user name"
USER_EMAIL="my@user.mail"
USER_BRANCH="main"
```

Якщо конфігурації немає, скрипт пропонує створити її та запитує значення в діалоговому режимі.

Під час створення:

- ім’я та email перевіряються на непорожність;
- назва гілки перевіряється через `git check-ref-format --branch`;
- порожнє введення назви гілки замінюється на `main`;
- `printf '%q'` екранує значення для подальшого читання Bash;
- `umask 077` обмежує права новоствореного файла його власником.

Наявна конфігурація завантажується через `source`.

### 2.4. Запуск

Скрипт запускається з директорії проєктів, наприклад `~/Projects`, яка сама не перебуває всередині Git-репозиторію.

```bash
cd ~/Projects
chmod +x TASK2.-Shell-scripting/utils/git-init.sh
```

Без аргументів — завантаження або створення конфігурації та показ довідки:

```bash
./TASK2.-Shell-scripting/utils/git-init.sh
```

З одним аргументом — створення локального репозиторію:

```bash
./TASK2.-Shell-scripting/utils/git-init.sh new_local
```

З двома аргументами — створення репозиторію або використання наявного та додавання `origin`:

```bash
./TASK2.-Shell-scripting/utils/git-init.sh new_remote \
    https://github.com/USER/REPOSITORY.git
```

`USER` і `REPOSITORY` у прикладі потрібно замінити відповідними значеннями.

### 2.5. Обробка станів директорії

| Стан директорії | Один аргумент | Два аргументи |
|---|---|---|
| Не існує | Створення та ініціалізація | Створення, ініціалізація та додавання `origin` |
| Існує й порожня | Ініціалізація | Ініціалізація та додавання `origin` |
| Уже є Git-репозиторієм | Повідомлення та завершення | Додавання `origin` |
| Містить файли, але не є репозиторієм | Повідомлення та завершення | Повідомлення та завершення |

Перевірка порожньої директорії враховує приховані файли.

Для наявного репозиторію режим із двома аргументами зберігає його поточні налаштування та README. Якщо `origin` уже існує, команда Git завершується з помилкою, не замінюючи його адресу.

### 2.6. Основні команди скрипту

Ініціалізація та локальні налаштування:

```bash
git init -b "$USER_BRANCH" -- "$dir"

git -C "$dir" config --local user.name "$USER_NAME"
git -C "$dir" config --local user.email "$USER_EMAIL"
git -C "$dir" config --local init.defaultBranch "$USER_BRANCH"
```

`git -C` виконує команду в зазначеній директорії. Параметр `--local` зберігає налаштування лише в цільовому репозиторії.

`git init -b` одразу задає початкову гілку. Запис `init.defaultBranch` після ініціалізації сам по собі вже створену гілку не перейменовує.

Створення README:

```bash
printf '# %s\n' "$1" > "$dir/README.md"
```

Додавання remote:

```bash
git -C "$dir" remote add origin "$2"
```

Скрипт не створює репозиторій на GitHub і не виконує автоматичних `commit`, `fetch`, `pull` або `push`. Додавання `origin` лише зберігає адресу.

### 2.7. Перевірки та обробка помилок

Скрипт перевіряє:

- наявність Git;
- допустиму кількість аргументів: 0, 1 або 2;
- запуск поза Git-репозиторієм;
- непорожність параметрів конфігурації;
- коректність назви гілки;
- назву цільової директорії;
- непорожність другого аргументу;
- стан цільової директорії.

Порожня назва директорії, `.` і `..`, а також назви з `/` відхиляються.

Повідомлення `[error]` спрямовуються у стандартний потік помилок через `>&2`. Перевірки `|| exit 1` завершують скрипт при невдалому виконанні відповідної команди.
